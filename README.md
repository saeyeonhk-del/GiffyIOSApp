# Giffy iOS — 첫 화면 구현 (0.1)

SwiftUI / iOS 17 이상 / Xcode 16 이상. 외부 패키지 없이 열 수 있는 iPhone 프로젝트입니다.

## 실행
1. Mac App Store에서 Xcode를 설치하고 한 번 실행해 iOS 개발 구성 요소 설치를 마칩니다.
2. Giffy.xcodeproj를 엽니다.
3. 상단 실행 대상으로 iPhone 시뮬레이터를 선택하고 실행(▶)합니다.
4. 실제 iPhone 실행 시 Signing & Capabilities에서 본인 개발 팀과 고유 Bundle Identifier를 설정합니다.

Xcode 27.2에서 iPhone 18 Pro 대상으로 빌드가 통과했습니다. 명령 실행 환경에서는 Swift 매크로와 시뮬레이터 접근이 제한되어 Xcode 앱에서 직접 빌드했습니다. 시뮬레이터 첫 부팅 및 화면 점검은 진행 중입니다. project.pbxproj의 plist 문법 검사도 통과했습니다. 앱 아이콘, 배포용 서명 및 App Store 메타데이터는 아직 없습니다.

## 구현된 화면
- Explore: Giffy 보라색·크림색, 지역 선택, 카테고리 필터, 상품 카드.
- Search: 상품명·매장·지역 검색, 카테고리와 조합, 결과 없음 안내.
- 상품 상세 → From 이름·메시지 작성 → 로그인 안내 시트.
- From 필수/50자 이내, 메시지 선택/200자 이내. 초과 입력은 유지하되 진행 불가.
- My Gifts 비로그인 안내. Apple·Google 버튼은 미연결 안내만 표시.
- 기존 /gift?code= 형식의 HTTPS URL 파서. 앱에 URL이 전달되면 수령 화면 안내를 표시. 실제 Universal Link 설정과 서버 조회는 미구현.

가격과 상품명은 공개 웹에서 확인한 3개 상품을 샘플로 사용합니다. 설명·지역 배치는 화면 검토용이며 실제 판매 정보가 아닙니다. 이미지는 SF Symbols 임시 그래픽입니다. 실제 로그인, 결제, 주문 생성, 바우처 발급, QR 표시, 공유, 푸시는 아직 연결되지 않았습니다. 샘플 모드는 앱에 명시되어 있으며 가짜 결제 성공이나 발급 결과를 만들지 않습니다.

## 다음 구현 순서
1. 기존 Base44 인증에서 네이티브 Apple·Google 계정 연결 지원 여부 확인. 이메일만으로 계정을 자동 병합하지 않고 제공자 식별자와 Giffy 계정을 검증해 연결. 계정 삭제 기능 포함.
2. 상품 API를 연결하고 로딩·오류·재시도 상태 구현. 상품 사용 조건을 데이터에 추가하고 샘플 문구 교체.
3. 서버에서 주문·최종 금액·From/메시지 저장 후 Stripe 결제 생성. 주문 소유자는 인증 계정 ID로 고정. 결제 수단 선택은 Stripe 연동 방식 검증 후 확정.
4. Stripe 이벤트 서명 및 실제 결제 성공 상태 검증. 이벤트/결제/주문 단위 중복 처리 방지와 발급 재처리 구현. Make Create a Row 단순 추가 대신 고유 제약 및 멱등 처리가 필요.
5. 결제·발급·구매 내역 저장을 클라이언트 복귀와 독립적으로 완료. Supabase orders를 발급 기준으로 사용하고 기존 Base44 Purchase와 서버에서 동기화. 양쪽 상태와 코드가 달라지지 않도록 검증.
6. orders의 unused와 Base44 completed/redeemed 상태를 명시적으로 매핑. expires_at을 바우처의 확정 만료일로 사용. 상품 validity_days 변경이 기존 바우처에 소급되지 않도록 처리.
7. 소유자 전용 My Gifts API와 비로그인 수령 API 분리. 기존 /gift?code= 링크 및 Vendor QR 처리와 호환되는 QR 페이로드 검증. 서비스 키는 앱에 넣지 않음.
8. Universal Links를 호스팅할 도메인·AASA 설정 검증 후 Associated Domains 연결. 수령자 웹 폴백 유지, 공유 시트·미리보기 구현. 실제 전송 완료를 공유 시트 열기와 혼동하지 않음.
9. APNs 및 기기 토큰 소유권/로그아웃 해제, 발급·리딤 알림, 만료 예정 발송 기준 확정 및 구현.

## 현재 구조에서 확인한 사항
- 웹 결제는 상품별 Stripe Payment Link로 이동합니다.
- Make는 Stripe 이벤트 → 변수 2개 → Stripe API 조회 → Supabase orders 행 생성 구조입니다. 수신 이벤트 종류, 결제 검증, 재시도 및 중복 제약은 아직 확인되지 않았습니다.
- Make 화면에서 expires_at=addYears(now;1), status=unused, Stripe 고객 이메일과 세션 ID 저장이 확인됐습니다.
- 웹 Success 화면이 Supabase 조회 후 Base44 Purchase를 생성합니다. 따라서 사용자가 돌아오지 않는 상황에도 서버에서 완료되도록 보완해야 합니다.

## 실행 후 수동 점검
- Explore 전체/각 지역/각 카테고리 조합, 빈 결과에서 필터 복구.
- Search 대소문자·상품명·매장·지역 검색, 검색 지우기, 상세로 이동 후 뒤로가기.
- From 공백만 입력 시 진행 불가, 50/51자 경계. 메시지 200/201자, 한글·이모지 입력.
- 로그인 시트 닫기 후 작성 내용 유지. 로그인 버튼은 미연결 안내만 표시.
- 작은 iPhone 및 큰 글자 설정에서 스크롤과 하단 버튼 접근 확인.
- 서버 연동 후: 결제 취소·네트워크 단절·앱 종료·중복 웹훅·결제 후 발급 지연·소유권 거부·리딤·만료·로그아웃 후 알림 진입 검증.
